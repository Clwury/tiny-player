# 设置界面

应用提供两种设置窗口，共用同一份配置与自动保存逻辑：

- **开发设置**：保留完整分类、搜索和缓存／解码调试参数，默认用于 dev 构建。
- **用户设置**：默认用于 release 构建，使用左侧分类、右侧内容的布局。侧栏分为外观、播放、内存缓存、磁盘缓存，保留主题、音轨语言、字幕语言、内存预算、磁盘缓存开关和容量上限。

两种窗口使用相同的侧栏样式、语言选项、磁盘缓存开关和容量输入控件。窗口默认尺寸为 960 × 680，最小尺寸为 900 × 600。

`TINY_DEV_SETTINGS` 只控制设置界面的展示，不修改播放配置或日志级别：

```sh
# dev 构建默认使用完整设置
cargo run --locked

# 在 dev 构建中预览用户设置
TINY_DEV_SETTINGS=0 cargo run --locked

# release 构建默认使用用户设置
cargo run --release --locked

# 发布版临时启用完整开发设置
TINY_DEV_SETTINGS=1 ./target/release/tiny-player
```

`1`、`true`、`on` 表示开发设置；`0`、`false`、`off` 表示用户设置。值忽略大小写及两侧空白。未设置、空值、无效值采用构建默认值，以 `debug_assertions` 区分 dev 和 release。环境变量在打开设置窗口时读取；已有设置窗口会直接激活。

## 用户设置的默认行为

新配置使用 Catppuccin Mocha 主题，音轨与字幕均为 `Default`，内存预算为 256 MiB，磁盘缓存关闭，磁盘容量上限为 4 GiB。语言列表的名称和顺序与开发设置完全相同。解码器追赶丢帧默认关闭，视频输出阶段的丢帧策略保持启用。开发设置仍可单独启用解码器追赶丢帧。

内存预算直接提供容量选项。切换容量时按默认比例分配 HTTP、前向和回看缓存预算：

| 内存预算 | HTTP 缓存 | 前向缓存 | 回看缓存 |
| --- | --- | --- | --- |
| 128 MiB | 16 MiB | 75 MiB | 25 MiB |
| 256 MiB（默认） | 32 MiB | 150 MiB | 50 MiB |
| 512 MiB | 64 MiB | 300 MiB | 100 MiB |
| 1 GiB | 128 MiB | 600 MiB | 200 MiB |
| 2 GiB | 256 MiB | 1200 MiB | 400 MiB |

该选择只调整容量预算，保留已有的预读时长、缓冲恢复、缓存模式等参数。重新选择当前容量也会保留已自定义的各层预算。该预算仅针对缓存，不代表应用总内存。

“启用磁盘缓存”和“磁盘缓存上限”是独立设置，与开发设置保持一致。上限以 GiB 为单位，支持直接输入整数和加减按钮（Shift 每次调整 10 GiB），关闭磁盘缓存时仍可修改上限。开关不会重置容量、清理策略或缓存目录。容量上限是 HTTP 与 Demux 共用的总预算：HTTP 元数据探测最多保留总预算的 1/8，且不超过 32 MiB，其余用于 Demux 媒体包。HTTP 仅写入开头 2 MiB 和显式的尾部元数据探测，避免重复落盘整部媒体；两层均复用已淘汰数据的文件空间。降低容量时，后台在内存预算内逐步恢复或搬移超额 Demux 包；内存不足时随播放消费及历史淘汰继续回收。正在读取或写入的磁盘块由引用保护，因此缩容不会立即截断仍然需要的数据。空值、0 和超出可表示范围的输入不会覆盖上次有效配置。

打开用户设置不会覆盖已有高级配置。不在容量选项中的内存总预算显示为“自定义”，直到主动选择新容量。磁盘容量仅在编辑后按 GiB 保存，打开窗口或切换开关均保留原值精度。主题或语言选择保留所有播放参数。两种窗口的更改均自动保存；缓存和解码设置继续通过现有通道应用到正在播放的会话，语言偏好用于后续播放的选轨。

## 前向预读与 seek

未启用磁盘缓存时，网络流默认持续读取压缩包，直到前向缓存达到 150 MiB（或当前选择的预算）。参考 mpv `demux/demux.c` 的 `read_packet()`，解码输出队列满和 seek 恢复状态不暂停压缩包预读；缓存内快进释放前向容量后立即补充。显式设置的预读时长、字节上限和 EOF 仍会停止读取。

HTTP 只在 Demux 达到实际字节／时长限制时暂停，并在容量释放后恢复，不再额外使用 90% 暂停、75% 恢复的水位。HTTP 默认回填滞回为 0，读取释放空间即可继续下载，复用当前响应。开发设置中显式指定的滞回秒数仍有效，`TINY_HTTP_CACHE_HYSTERESIS_SECS=0` 可覆盖该值；“自动滞回”只影响 Demux 的时长限制。

seek 恢复期间，预读线程仅在有消费者实际等待缓存锁时短暂让出执行机会，不再逐包等待 100 ms。回看缓存超过前向与回看总预算 8 MiB 后，会在继续预读前执行有时间／步数上限的回收，并在各轮回收间释放锁。正常的包大小、完整 GOP 和读取中的数据保护可能使实际用量短暂超过预算。

## 磁盘缓存与内存

默认播放缓存目录为 `~/.cache/tiny-player`，不再使用系统临时目录。已设置的自定义目录和 `TINY_HTTP_CACHE_DIR` / `TINY_DEMUX_PACKET_CACHE_DIR` 环境变量仍然优先。默认文件创建后即解除目录链接，但打开的文件仍可读写，并在会话结束时释放；目录中看不到文件不代表未使用磁盘缓存。

开启磁盘缓存后，Demux 前向／回看设置共同约束常驻缓存内存，同时以相同比例分配 Demux 磁盘预算。媒体窗口上限为相应的内存份额加磁盘份额。默认 4 GiB 磁盘预算中 HTTP 占 32 MiB，Demux 占 4064 MiB；按 150:50 分配后，媒体前向上限约为 3198 MiB，基础回看上限约为 1066 MiB。空闲前向空间仍可捐给回看。显式预读时长、EOF、常驻内存压力或磁盘故障可能先于该媒体上限停止预读；关闭回看时不会为其分配磁盘份额。

新包首先进入内存，独立的磁盘线程优先写出远离播放位置的包。热点以当前读指针附近前向约 3 秒、后向约 1 秒为目标，容量不超过 Demux 常驻预算的三分之一且最多 32 MiB；当前各轨读取头优先保留。冷包在后台提前读取，消费者遇到未就绪冷包时返回等待信号，读指针保持不变。后台仅保留一个正在执行的包 I/O，待处理列表只存包 ID；写满或慢盘会触发预读背压，不会无限堆积 payload 副本。关闭磁盘缓存只停止新的写入，已有磁盘包仍可读取。

状态显示分别报告媒体前向字节、缓存常驻内存估算、磁盘有效数据、文件长度和缩容待回收量。常驻估算包含包 payload、FFmpeg 属性及 side data、队列和索引开销；磁盘上的 payload 不再重复计入常驻内存。热点副本与磁盘数据分别计入对应存储层，媒体字节只计一次。文件长度可能含可复用空洞，因此不等于有效媒体量。HTTP 内存统计为其持有的数据字节。上述缓存预算不包括解码器、音视频输出、GPU 或操作系统文件页缓存，完整包、GOP 保护和单次后台 I/O 也可能带来短暂超额。
